# Audit Spekit API token lifecycle

Spekit's activity feed records its **own** credential events. Two of the 21 `activity_type` values are `api_auth_token_generated` and `api_auth_token_revoked`, which makes this API self-auditing: you can answer "who minted an API token, when, and from where" without any admin console access.

Use this when asked to review Spekit API access, prepare an access review, or check whether a departed admin left a live token behind.

## Authenticate

`Authorization: Token <SPEKIT_API_TOKEN>` — the literal `Token ` prefix is required. Only Account Admins can mint tokens (Spekit web app → Settings → API Tokens).

## Steps

1. **Pull generations.** Call `v1_analytics_user_activities_list` with `activity_type=api_auth_token_generated`, plus `start_date` and `end_date` as RFC 3339 date-times covering the review window, and `page_size=100`.
2. **Page it.** Follow `next` verbatim until it is null. The envelope is `{count, next, previous, results[]}`.
3. **Pull revocations.** Repeat with `activity_type=api_auth_token_revoked` over the same window.
4. **Read each record.** Every result carries `user` (the full user object — `id`, `first_name`, `last_name`, `email`, `is_active`, `created_on`, `teams[]`), `created_on`, `activity_type`, `activity_id` and `ip`.
5. **Pair them.** The operation description documents the token payload fields for these two activity types as `id`, `key`, `expiry`, `expiry_dt`, `description` and `deleted`. These are described in prose in the spec, not modelled in `components.schemas` — read what the response actually returns rather than assuming a typed shape.
6. **Find the unrevoked.** A generation with no matching revocation is a token that is still live unless its expiry has passed. Flag every one where `deleted` is false and `expiry_dt` is in the future or absent (never-expire).
7. **Cross-check the actor.** Call `v1_users_list` and page it. Any token whose generating user now has `is_active: false` is a live credential held by an inactive account — report those first.

## Report

For each finding give: the token `description` (the label the admin typed, e.g. "Tableau Reporting Sync"), the generating user's name and email, `created_on`, `expiry`/`expiry_dt`, the `ip`, and whether a revocation was seen.

Call out explicitly:
- Never-expire tokens. Spekit allows an expiry of "Never Expire"; those are the highest-risk entries.
- Tokens generated by users who are no longer `is_active`.
- Generations from an unfamiliar `ip`.

## Constraints

- 30 requests / 10 seconds; a `429` comes back bare with no `Retry-After`. Back off exponentially.
- `page_size` maxes at 100.
- This API cannot revoke anything. It is `GET`-only. Revocation happens in the Spekit web app under Settings → API Tokens — say so in the remediation rather than attempting a call.
